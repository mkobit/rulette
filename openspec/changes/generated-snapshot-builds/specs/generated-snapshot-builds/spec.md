## ADDED Requirements

### Requirement: Homogeneous explicit generated snapshot inputs

Rulette SHALL treat a snapshot generated by Beads, OpenSpec, CI, or another external tool as an ordinary caller-supplied source input.

One generated-snapshot invocation SHALL select exactly one statically compiled native frontend through an explicit `--from <frontend>` value or an unambiguous `--from auto` resolution, or it SHALL select one explicitly named Rulette graph JSON or graph TOML reader.

`--from auto` SHALL succeed only when every discovered native input resolves unambiguously to the same native frontend.

Graph JSON and graph TOML SHALL require explicit reader selection and SHALL NOT use `--from auto`.

Every explicit input in the invocation SHALL use the selected decoder family.

The invocation SHALL reject mixed native frontends, graph JSON plus graph TOML, and native plus graph interchange inputs.

Native inputs SHALL be existing regular files, directories, tar archives, or gzip-compressed tar archives accepted by the selected frontend.

Graph interchange SHALL require explicit reader selection and exactly a supported graph version and schema.

At most one input may be standard input, and standard input SHALL be an explicitly selected tar archive, gzip-compressed tar archive, graph JSON document, or graph TOML document.

Plain native standard input SHALL be rejected until Rulette defines a naming and layout contract for it.

#### Scenario: Compiling homogeneous generated native snapshots

- **WHEN** a caller selects one supported native frontend and supplies multiple compatible existing files or directories generated outside Rulette
- **THEN** Rulette SHALL parse every input through that selected frontend
- **AND** SHALL NOT invoke an input producer.

#### Scenario: Rejecting mixed graph encodings

- **WHEN** a caller combines graph JSON and graph TOML inputs in one generated-snapshot invocation
- **THEN** Rulette SHALL exit with a non-zero usage error before graph aggregation.

#### Scenario: Rejecting plain native standard input

- **WHEN** a caller selects a native frontend and supplies plain standard input
- **THEN** Rulette SHALL reject the input as unsupported source syntax
- **AND** SHALL NOT infer a native filename or package root.

### Requirement: Classified discovery and bounded grouping

One shared resource ledger SHALL span every explicit input and the sole standard-input stream in a generated-snapshot invocation.

The existing 32 MiB per-resource limit and 256 MiB total invocation limit SHALL apply through that ledger across the complete source set.

The selected native frontend SHALL classify every discovered observation as package content, retained unsupported content, an unrecognized-file warning, or fatal malformed input.

An explicitly selected native frontend that produces zero packages after classifying its complete source set SHALL fail with unsupported source syntax.

Native package grouping SHALL use the pair of content-safe explicit-input identity and normalized package root.

Rulette SHALL NOT merge resources from distinct explicit inputs during native grouping, even when their normalized package roots are equal.

#### Scenario: Separate snapshots keep equal roots separate

- **WHEN** two explicit native inputs contain resources below the same normalized package root
- **THEN** Rulette SHALL group their resources as separate package candidates before graph aggregation.

#### Scenario: Unclassified observation fails

- **WHEN** the selected frontend cannot classify a discovered observation as package content, retained unsupported content, an unrecognized-file warning, or fatal malformed input
- **THEN** Rulette SHALL fail before graph aggregation or target processing.

#### Scenario: Shared budget spans archive and graph inputs

- **WHEN** a generated-snapshot invocation combines several explicit inputs and one accepted standard-input stream
- **THEN** Rulette SHALL enforce the existing 32 MiB per-resource and 256 MiB total limits through one shared ledger across the entire source set.

### Requirement: Deterministic aggregate graph and collision reporting

Rulette SHALL form package candidates from every classified native input or decoded graph document before it constructs the aggregate `CompilationGraph`.

Rulette SHALL represent every decoded package as a transient aggregation candidate containing the validated package unchanged and a separate content-safe outer explicit-input identity.

For graph interchange, Rulette SHALL merge candidate packages and diagnostics in stable order without serializing the outer identity into `SourceProvenance` or `CompilationGraph` and without overwriting existing package provenance.

Rulette SHALL compute every candidate package ID and semantic identity under graph kernel rules and collect candidates in deterministic indexes by both keys.

Before graph construction, Rulette SHALL report every semantic-identity collision group and every package-ID collision group in stable key order.

Each collision group SHALL list its shared key, every candidate package ID, existing package provenance, and separate outer explicit-input identity for every candidate in deterministic outer-identity order.

Byte-identical duplicate packages SHALL remain collisions.

Only a collision-free candidate set SHALL become one `CompilationGraph` ordered by documented stable graph keys.

Capability and lowering findings SHALL retain only existing package `SourceProvenance` and SHALL NOT include transient outer explicit-input identity.

#### Scenario: All collision groups are reported

- **WHEN** one source set contains duplicate semantic identities and duplicate package IDs in distinct candidate groups
- **THEN** Rulette SHALL report every group in stable key order before target processing
- **AND** SHALL NOT stop after the first collision.

#### Scenario: Graph inputs retain outer diagnostic provenance

- **WHEN** two explicitly selected graph JSON documents contribute colliding packages
- **THEN** the collision diagnostic SHALL identify each package with existing package provenance and separate content-safe outer explicit-input identity in deterministic outer-identity order
- **AND** SHALL NOT serialize or overwrite package provenance with that outer identity.

### Requirement: One-way multi-target artifact lifecycle

After complete aggregation and collision validation, Rulette SHALL normalize and deduplicate target spellings under existing target-resolution behavior and require one or more unique resolved targets from the compiled-in backend registry.

Backend resolution, capability analysis, and lowering SHALL NOT run against a partial graph.

Each selected backend SHALL deterministically produce an independent typed artifact set from the fully validated graph without writing files.

The existing all-or-nothing stage and apply transaction SHALL cover every selected target artifact set.

Neither a staged artifact nor a published destination SHALL become an implicit input to a later build.

#### Scenario: Multiple targets lower after aggregate validation

- **WHEN** a valid aggregate graph has two explicitly selected supported targets
- **THEN** Rulette SHALL lower two independent target artifact sets after collision validation
- **AND** SHALL stage and apply them through the existing atomic multi-target transaction.

#### Scenario: Duplicate target spellings resolve once

- **WHEN** a caller supplies repeated target spellings that normalize to one existing target
- **THEN** Rulette SHALL resolve one unique target artifact set
- **AND** SHALL not reject the invocation for naming the same target more than once.

#### Scenario: A checked destination is never imported

- **WHEN** `check` observes that a generated destination differs from its deterministic artifact
- **THEN** Rulette SHALL report drift without writing the destination
- **AND** SHALL NOT parse or merge the destination into the compilation graph.

### Requirement: Derived artifact drift policy

Rulette SHALL treat each target artifact as derived output from the explicit source snapshots, selected targets, compiler version, and compiled-in mappings.

Manual edits to a staged artifact or a live destination SHALL NOT modify, merge into, or synchronize with a source snapshot, graph package, generator, or future build.

Staged artifact modifications SHALL fail plan integrity verification before apply.

Live destination modifications SHALL be reported as drift by check and as a conflict by apply unless the caller supplies existing explicit replacement authority.

Rulette SHALL retain no state or history for output-to-source association or synchronization conflict resolution.

#### Scenario: Manual destination edit is a conflict, not a merge input

- **WHEN** a caller modifies a live destination after a stage is created
- **AND** applies the stage without explicit replacement authority
- **THEN** Rulette SHALL fail with a destination conflict
- **AND** SHALL NOT merge the manual edit into the staged artifact or source graph.

### Requirement: Static execution and extension boundary

The Rulette binary SHALL contain every parser, frontend, backend, transform, and target mapping used by a generated-snapshot build.

Rulette SHALL NOT execute Beads, OpenSpec, external generators, shell commands, hooks, scripts, or source content during source parsing, graph aggregation, lowering, check, stage, or apply.

Rulette SHALL NOT dynamically discover or load plugins, interpreters, runtime code, dynamic libraries, shared libraries, network adapters, or transform implementations.

Text or opaque resources that name a command, generator, hook, plugin, script, library, or URL SHALL have no executable effect.

Future JSON5, YAML, TOML, or code-like configuration support is out of scope for this capability and, if added under `rulette-5n4`, SHALL select only transforms compiled into the binary.

#### Scenario: A generated hook definition cannot execute

- **WHEN** a supported snapshot contains an opaque resource that declares a hook or command
- **THEN** Rulette SHALL preserve or classify that resource only under the existing frontend and backend capability rules
- **AND** SHALL NOT invoke the declared command or hook.
