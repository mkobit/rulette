# Rulette competitor benchmark decisions

This synthesis completes the analysis in `rulette-l8r.3` using the completed `rulette-l8r.1` and `rulette-l8r.2` evidence.
Rulette should match useful inspection and CI checks, beat the recorded publication-authority baseline, and retain its offline compiler boundary.
It cannot yet claim universal semantic fidelity or automatic interoperability with skills CLI installations.
`rulette-ka2` should be revised before execution; `rulette-onj` remains an open human gate.

## Evidence and decision authority

The [Agent Skills comparison](rulette-vs-agent-skills.md) pins `skills@1.7.2` to `671e8c320810d36fed80fac5f1a2c1bf7e82d812` on October 10, 2026.
Its [40 command records](benchmarks/skills-1.7.2-results.json) distinguish observed commands from source-reviewed and advertised capabilities.

Its [retrieval index](benchmarks/rulesync-29.0.0-sources.json) links and hashes official primary documents; lifecycle behavior is stated/source-reviewed, not runtime-observed.
No competitor experiment, migration fixture, or test was repeated for this synthesis.

“Shipped” below means implemented in the current repository source, not independently measured in a distributed release.
“Intent” means a documented contract; it does not override a conflicting implementation or architectural constraint.
“Proposed” means a benchmark recommendation requiring approval before product or specification work.
Match and beat describe recommended outcomes, not approval to add functionality or proof that every criterion already passes.
Deliberate non-goals reaffirm the existing compiler boundary.
An unresolved human design question leaves the decision open rather than choosing a product response implicitly.

The current [PRD](2026-04-11-prd.md), [command reference](2026-04-11-man-page.md), [generated CLI help](cli/rulette.md), and [capability matrix](2026-04-25-comparison-matrix.md) are compared with source and all three base specifications below.

## Required user journeys

Counts exclude executable installation, acquisition outside the selected product, source editing and human review time.
Skills counts below are supported by recorded commands; Rulesync counts describe official workflows; Rulette counts follow source and documentation rather than new runtime measurements.
No side-by-side time-to-success measurement exists.
`ka2` should record elapsed time, command count, help lookups, failed attempts and concepts understood for each journey without turning existing competitor fixtures into new parity experiments.

Digest coverage in D07 is specific: [package identity](../src/ir/graph.rs) hashes graph version, package kind, semantic identity, ordered resource paths, executable flags and resource-content digests.
It does not by itself attest every provenance or frontend-payload field.
The graph digest covers canonical graph bytes; the [plan digest](../src/publication/plan.rs) covers raw plan bytes, including bound roots and recorded loss acceptance.
Each artifact digest covers its bytes, with its executable flag checked separately by [apply](../src/publication/apply.rs).
