# Red team review: staff engineer critique

2026-04-11

## Severity: high

### 1. Strategy and codebase describe different CLIs

The CLI in `cli.rs` has `Add`, `List`, `Init`, `Transform`, `Inspect`.
The strategy describes `parse`, `emit`, `validate`, `fetch`, `lock`, etc.
The existing CLI was a prototype.
The strategy replaces it — the codebase needs to be updated to match.

**Resolution:** The strategy is the source of truth. The existing `cli.rs` is scaffolding from early exploration and will be rewritten to match the PRD.

### 2. IR cannot represent format-specific semantics

The IR is `SkillMetadata` + `body: String`.
Cursor MDC has `alwaysApply`, `globs`, `description` as structured fields.
Codex has directory-scoped hierarchy.
Claude has tool permissions.
The IR has no way to carry these.

The `transform --filter 'always_apply == true'` example requires a field that does not exist in the current IR.

**Resolution:** The IR needs a format-specific extension map (like the existing `extra: HashMap<String, serde_json::Value>`) that preserves format-native fields through the pipeline.
When emitting to a target that supports the field, it passes through.
When emitting to a target that does not, it is silently dropped (with a warning in `--strict` mode).
This is lossy by design — the document should be explicit about which transforms are lossless vs lossy, per format pair.

### 3. v0.1 scope is too large

14 commands total is too many.
Even the stated v0.1 (5 commands including `transform` with expression language and `--shell` pipeline) is ambitious.

**Resolution:** v0.1 is `parse`, `emit`, `inspect`, plus a `convert` convenience command.
`transform` and `validate` move to v0.1.1 or v0.2.
State this honestly in the PRD.

### 4. Agent Skills may be the right canonical IR

Agent Skills is adopted by 20+ tools.
The current `Skill` struct in `agent_skills.rs` is essentially the IR already.
Inventing a separate "Rulette IR" that is isomorphic to Agent Skills creates cognitive overhead.

**Resolution:** Use Agent Skills as the canonical IR format.
The Rulette IR _is_ Agent Skills + extension fields for format-specific metadata.
The JSON serialization follows the Agent Skills schema.
This positions Rulette as the build tool for the Agent Skills ecosystem rather than a competitor to it.

### 5. Obsolescence risk from Agent Skills convergence

If all tools natively read Agent Skills, format translation loses value.
The surviving value is: supply chain integrity, transform pipelines, policy checking, and user-scope management.

**Resolution:** Lean into the supply chain and determinism story as the primary value proposition, not format translation.
Format translation is the gateway feature, not the moat.

## Severity: medium

### 6. `parse | emit` vs `convert` for the 80% case

Requiring two piped commands for "convert this Cursor rule to Claude format" is a tax.

**Resolution:** Add `rulette convert --from cursor-mdc --to claude` as a convenience that does parse+emit internally.
This does not break composability — power users still pipe individual commands.

### Flat vs grouped subcommands

Docker-style grouping (`rulette rule parse`, `rulette source fetch`) was considered and rejected for v0.1.
With 4 commands, grouping adds ceremony without value.
Flat commands compose better in pipes (`rulette parse | rulette emit` vs `rulette rule parse | rulette rule emit`).
The `protoc`, `jq`, `tar` precedent supports flat.
If command count exceeds ~12, groups can be added as a backwards-compatible alias layer.

### 7. Checksums without signatures are self-referential

If an attacker can modify rules, they can modify the lockfile too.

**Resolution:** Acknowledge this limitation in the threat model.
SHA-256 lockfiles protect against accidental drift and MITM, not compromised repos.
Plan for Sigstore/cosign signing support as a v0.2 enhancement.
This is the same model as `cargo` and `go.sum` — pragmatically useful even without signatures.

### 8. `--allow-mutable --no-verify` is two flags for one decision

If `--no-verify` requires `--allow-mutable`, they are not independent.

**Resolution:** Consider a single `--insecure` flag.
Or keep both flags but make them independently meaningful:

- `--allow-mutable` allows fetching a non-pinned ref (but still verifies the download matches the ref)
- `--no-verify` skips content verification (but still requires a pinned ref)
- Both together: fully unchecked

This makes them orthogonal, not redundant.

### 9. `emit` as a verb

"emit" is compiler jargon.
Most users would expect `export`, `write`, or `generate`.

**Resolution:** Keep `emit` — it is precise and the `protoc` audience will recognize it.
The `convert` convenience command handles the non-compiler-savvy user.
If user testing shows confusion, revisit.

### 10. CI/CD examples beyond Bazel

The Bazel example is detailed.
GitHub Actions, GitLab CI, and other CI systems are not mentioned.

**Resolution:** Add a GitHub Actions example to the PRD.
The static binary story makes this trivial (`curl | tar | rulette`), but users need to see it written out.

## Severity: low

### 11. Realistic v0.1 target count

The codebase has 4 tool targets (Claude, Cursor, Codex, Gemini).
The strategy says "fewer initially" without committing.

**Resolution:** State the v0.1 targets explicitly: Claude, Cursor MDC, Codex, Agent Skills (as canonical IR), JSON IR.
Copilot, Windsurf, and Gemini are trivial additions (plain markdown / simple JSON) and can ship in v0.1 or v0.1.1.

### 12. "Compiler" naming

"Compiler" oversells. "Transpiler" is accurate but jargony.

**Resolution:** Use "tool" in user-facing copy. Use the `protoc` analogy. Let the architecture speak for itself.
