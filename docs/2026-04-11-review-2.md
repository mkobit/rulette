# Red team review 2: internal consistency audit

2026-04-11

Second review focused on internal consistency across all docs after the entity model expansion.

## Findings and resolutions

### 1. `extra` vs `extensions` dual map (severity: high)

Having both `extra` (passthrough) and `extensions` (well-known) maps creates a migration problem when keys move between maps across IR versions.

**Resolution:** Merged into a single `extra: HashMap<String, Value>` map.
Well-known keys use the `rulette:` prefix convention.
Unknown keys are passthrough.

### 2. `--format` flag ambiguity (severity: high)

`--format` means input format on `parse` but output format on `emit`.
This is confusing and error-prone.

**Resolution:** Replaced with `--from` (input format detection) and `--to`/`-t` (output target format).
Both are unambiguous and consistent across all commands.

### 3. `command` entity kind redundancy (severity: medium)

Claude skills already subsume commands — a skill with `activation: manual` is a slash command.
Having a separate `command` entity kind creates an artificial distinction.

**Resolution:** Dropped `command` as a separate entity kind (7 -> 6 kinds: rule, skill, hook, mcp-server, agent, permissions).
Skills with manual activation mode represent slash commands.

### 4. Missing concrete IR examples (severity: medium)

The IR design section described the schema abstractly but had no concrete JSON examples showing real-world entities.

**Resolution:** Added 3 concrete IR JSON examples: a Cursor MDC rule, a Claude Code skill with tool-access extensions, and a mixed document containing a rule + MCP server.

### 5. Announcement contradicted PRD on CLI structure (severity: medium)

Announcement text said "grouped by domain, like Docker" but showed flat commands and the PRD specified flat commands.

**Resolution:** Fixed announcement to say "flat and top-level, like protoc and jq".

### 6. Entity taxonomy missing format support info (severity: low)

The entity kind table listed kinds but didn't show which source formats support which entity types.

**Resolution:** Added "supported in" column to the entity taxonomy table.

### 7. Permissions and settings not documented (severity: low)

The `permissions` entity kind was listed but its semantics and IR representation were not documented.

**Resolution:** Added permissions/settings documentation section covering Claude's tool permissions, Cursor's settings overrides, and how they map to the IR.

### 8. No honest positioning section (severity: low)

The PRD described what Rulette does but didn't honestly address competitive positioning, adoption risk, or the "what if Agent Skills wins" scenario.

**Resolution:** Added positioning and adoption section covering v0.1 target audience (Bazel/security users), surviving value if format convergence happens, and explicit non-goals.

### 9. Mixed directory parsing undefined (severity: low)

No documentation on what happens when `rulette parse` encounters a directory containing multiple formats (e.g., `.cursor/rules/` alongside `CLAUDE.md`).

**Resolution:** Added mixed directory parsing documentation — auto-detection by file extension/convention, one entity per detected file, conflicts reported as warnings.

### 10. Lossy conversion default behavior undefined (severity: low)

No documentation on what happens when emitting to a format that can't represent all fields (e.g., Cursor `globs` -> Claude which has no glob concept).

**Resolution:** Added lossy conversion section — default behavior warns to stderr but produces output; `--strict` mode fails on information loss.
