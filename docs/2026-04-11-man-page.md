# Rulette 0.1 command reference

## Synopsis

Rulette compiles explicitly supplied local AI-agent guidance into a deterministic compilation graph.
It then selects exact packages, lowers them to a named native target, and stages artifacts for review before any separately authorized publication.

## Concepts

### Compilation graph

`CompilationGraph` is the v0.1 library and interchange value.
It contains graph-versioned packages in stable package-identifier order and stable diagnostics.
It replaces the retired flat document and entity APIs.
Its JSON and TOML representations are strict explicit graph inputs when their graph version and invariants validate.

### Packages

A package is the smallest native materialization unit.
Rules and skills are portable package kinds.
Skill packages retain their primary `SKILL.md` instruction and any opaque companion resources.
Native-only semantics remain unsupported packages rather than being rewritten as portable content.

### Core harnesses

Rulette supports graph frontends and lowering targets for Codex, Claude, Cursor, OpenCode, and Antigravity.
The source frontend is either selected explicitly or safely auto-detected from one unambiguous native layout.
Rules, skills, primary instructions, and safe package resources are the narrow v0.1 semantic portability contract.
Agents, hooks, MCP settings, permissions, plugins, registries, and fetch behavior are outside that contract.

### Selection

Selection matches exact package identifiers.
No selection retains every package in stable order.
Selection does not filter text, rename metadata, set fields, merge packages, or deduplicate content.

### Loss handling

Lowering classifies each selected package and resource as supported, lossy, or dropped.
Loss blocks staging under the strict default.
`--allow-lossy` accepts reviewed loss findings and can continue to staging while keeping the findings attached to the result and plan.

## Commands

### `transform`

`transform` is the compiler entry point.
It observes explicit inputs, compiles one graph, applies exact package selection, analyzes requested native targets, and coordinates the staged-publication workflow.
It never uses a raw native output path as implicit publication authority.

### `inspect`

`inspect` renders a compilation graph or reports the capability findings for core targets.
Coverage remains informational unless the caller requests its explicit failure gate.

### `schema`

`schema` renders the JSON Schema for `CompilationGraph`.
It does not expose schemas for retired flat documents, legacy parser structures, or direct native emitters.

## Input and safety

Inputs are local files, directories, standard input, or safe tar archives supplied by the caller.
An explicit graph JSON or TOML input re-ingests one validated `CompilationGraph` without falling back to the retired entity document.
Rulette rejects unsafe paths, links in archive inputs, duplicate normalized archive members, malformed graph values, and identity collisions before lowering or staging.
The binary does not fetch network content, discover configuration, load dynamic code, or persist local state.
It has no registry or fetch subsystem.

## Distribution

v0.1.0 ships `rulette-v0.1.0-x86_64-unknown-linux-musl.tar.gz`.
The archive contains a fully static Linux binary with no runtime dependencies.
Verify the archive with its `.sha256` sidecar before extracting `rulette`.

## Publication

Lowering produces target-relative artifacts rather than mutating a native destination.
Staging records deterministic artifacts, mappings, selected graph identity, and accepted loss findings for review.
Applying a staged plan requires separate explicit authorization and validates the plan before destination mutation.
`--stage` never publishes a live destination.
`--apply` is the only publishing operation and requires both `--expect-plan-sha256` and an explicit authorized root.

### Staging

Use repeatable `--target format@scope` values with `--stage DIRECTORY`.
Each project target requires `--project-root DIRECTORY`.
Each user target requires `--user-root format=DIRECTORY`.

```text
rulette transform RULES \
  --target codex@project \
  --project-root . \
  --stage .rulette/stage
```

The compilation graph remains on standard output unless `--quiet` is set.
Successful staging writes the plan digest to standard error.

Use `--check` with the same target and source-root arguments to classify destinations without creating a stage.
It prints sorted `entry-id status` lines to standard error and exits zero only when every destination is unchanged.

### Applying a reviewed plan

Apply uses the exact staged plan digest and separate root authority.

```text
rulette transform \
  --apply .rulette/stage/rulette.plan.json \
  --expect-plan-sha256 sha256_... \
  --allow-project-root .
```

Use `--allow-user-root format=DIRECTORY` for every user-scope target in the plan.
Use `--replace` only to replace a conflicting destination.
Plan `--check` uses the same authority and digest arguments but makes no changes.

### Migration from direct outputs

Replace any direct native output path with a stage directory and explicit root authority.
Remove legacy `--out` and `--to` native-output invocations.
Review the staged plan and then invoke `--apply` with its exact digest and `--allow-project-root` or the required user-root authorization.
Keep transform configuration limited to `inputs`, `targets`, and sorted `select` values.
Configuration cannot carry stage locations, roots, replacement permission, loss permission, or destination paths.
