## NAME

**rulette** — stateless compiler for AI coding assistant configuration

## SYNOPSIS

```sh
rulette <command> [options] [input...]
```

## DESCRIPTION

Rulette parses AI coding assistant configuration — rules, skills, hooks, MCP servers, commands, sub-agents, and permissions — from any supported format into a typed intermediate representation (IR), applies an ordered transformation pipeline, and emits output in any supported target format.

It is designed for deterministic, reproducible builds of AI configuration.
It never touches the network unless explicitly asked.
It has no configuration files, no local state, and no daemon.

All commands are flat top-level subcommands, like `protoc`, `jq`, and `tar`.

## COMMANDS

### `rulette transform [input...]`

The primary command for all source-to-sink operations.
It handles parsing, filtering, renaming, and emitting rules to any target format.
Automatically detects input format from file extension and content.

**Options:**

```text
--from <format>           Force input format detection (auto, skill-md, agent-skills,
                          claude, cursor-mdc, cursor-legacy, codex, windsurf, copilot,
                          gemini, ir-json, ir-toml)
--to <format>             Target output format: claude, cursor-mdc, codex, windsurf,
                          copilot, gemini, agent-skills, ir-json, ir-toml
-o, --out <path>          Output path (file or directory) or multiple targets via format:path
--scope <scope>           Output scope: project (default) or user.
                          When user, resolves --out to user-global config paths
                          (e.g., ~/.claude/skills/ for claude, ~/.cursor/rules/ for cursor-mdc)
--filter <expr>           Keep only rules matching expression (e.g., 'license == "MIT"')
--exclude <expr>          Remove rules matching expression
--rename <from>=<to>      Rename a metadata field value
--set <field>=<value>     Set a metadata field
--config <path>           Load transform pipeline from TOML file
--dedup                   Remove duplicate entities from the IR stream
--strict                  Fail on lossy conversion warnings or parse errors
```

**Examples:**

```text
# Parse Cursor rules and emit as Claude skills
rulette transform .cursor/rules/ --to claude --out .claude/skills/

# Convert a single skill between formats
rulette transform SKILL.md --to gemini --out GEMINI.md

# Filter stable rules and emit to multiple targets
rulette transform rules/ --filter 'status == "stable"' \
  -o claude:.claude/skills/ \
  -o cursor-mdc:.cursor/rules/

# Emit personal rules to global tool paths
rulette transform ~/dotfiles/ai-rules/ --to claude --scope user
```

### `rulette inspect [input...]`

Pretty-print the IR for debugging.
Shows parsed structure, metadata, body preview, and detected issues.
Reports which fields will be lost when emitting to a target format.

**Options:**

```text
--to <format>             Target format to dry-run emission and show capability analysis
```

**Examples:**

```text
# Inspect the IR of a rule directory
rulette inspect rules/

# Analyze what Claude will receive and see lossy conversion warnings
rulette inspect rules/ --to claude
```

### `rulette schema`

Output JSON Schema for the IR or a specific target format.

**Options:**

```text
--format <format>         Format to output schema for: ir (default), claude,
                          cursor-mdc, agent-skills, gemini, codex
```

**Examples:**

```text
rulette schema
rulette schema --format claude
```

## EXAMPLES AND PIPELINES

Rulette embraces the Unix philosophy: it acts as a thin transformation layer, auto-detecting inputs, and relying on standard pipelines for complex processing.

### Auto-detecting Inputs

Rulette automatically detects the format and nature of the input, whether it's a file, a directory containing rules, or an archive:

```sh
# Parse a directory of mixed rules and output IR JSON to stdout
rulette transform ./my-rules/

# Read from stdin
cat SKILL.md | rulette transform --to gemini --out ./gemini-rules/
```

### Multiple Target Outputs (All-or-Nothing)

You can specify multiple outputs simultaneously. Rulette will compute all transformations and write to all destinations. If any transformation fails, the entire operation fails (all-or-nothing), ensuring consistency across your environments.

```sh
# Generate Gemini rules, Cursor rules, and a combined JSON IR file simultaneously
rulette transform ./rules/ \
  -o gemini:.gemini/rules/ \
  -o cursor-mdc:.cursor/rules/ \
  -o ir-json:./build/rules.json
```

### External Filtering and Transformation Pipelines

Instead of implementing a robust internal filtering engine, Rulette encourages emitting the Intermediate Representation (IR) as JSON, processing it with standard tools like `jq`, and piping it back into Rulette.

```sh
# Filter skills by name using jq, then convert the remaining ones to Claude format
rulette transform marketplace.tar.gz --to ir-json \
  | jq -c '.entities | map(select(.metadata.name | test("auth-.*")))' \
  | rulette transform - --to claude --out ./filtered-claude-skills/
```

## GLOBAL FLAGS

```sh
--to, -t            Output/target format (json, toml, claude, cursor-mdc, codex, windsurf, copilot, gemini)
--from              Input/source format (auto-detected if omitted)
--out, -o           Output path (stdout if omitted)
--scope             Output scope: project (default) or user
--quiet, -q         Suppress non-error output
--strict            Fail on warnings (including lossy conversion warnings)
--no-color          Disable colored output
--log-level         Log verbosity (error, warn, info, debug, trace)
```

## ENVIRONMENT

```text
RULETTE_LOG          Log level (error, warn, info, debug, trace)
RULETTE_COLOR        Force color output (auto, always, never)
NO_COLOR             Disable color output (standard convention)
```

## EXIT CODES

```text
0    Success
1    General error
2    Parse error
3    Validation error
4    Integrity verification failed
```

## FILES

Rulette does not read or write any implicit configuration files.
All paths are explicit CLI arguments.

The following file conventions are recognized by `rulette parse` for format auto-detection:

```text
SKILL.md                   Agent Skills format (YAML frontmatter + markdown body)
*.skill.md                 Generic skill (TOML frontmatter + markdown body)
*.rulette.json             Rulette IR (JSON)
*.rulette.toml             Rulette IR (TOML)
CLAUDE.md                  Claude Code rules
.cursorrules               Cursor legacy rules
.cursor/rules/*.mdc        Cursor MDC rules
AGENTS.md                  OpenAI Codex rules
.windsurfrules             Windsurf rules
.github/copilot-instructions.md    GitHub Copilot instructions
GEMINI.md                  Gemini Code Assist rules
.gemini/settings.json      Gemini Code Assist settings
```

The following user-scope paths are resolved by `--scope user`:

```text
claude          ~/.claude/skills/ (skills/commands) & ~/.claude/settings.json (settings/hooks/MCP)
cursor-mdc      ~/.cursor/rules/
codex           ~/.codex/AGENTS.md
copilot         ~/.config/github-copilot/instructions.md
gemini          ~/.gemini/GEMINI.md
windsurf        ~/.windsurf/windsurfrules
```
