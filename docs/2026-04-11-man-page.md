# Man page

_2026-04-11_

## NAME

**rulette** — stateless compiler for AI coding assistant configuration

## SYNOPSIS

```
rulette <command> [options] [input...]
```

## DESCRIPTION

Rulette parses AI coding assistant configuration — rules, skills, hooks, MCP servers, commands, sub-agents, and permissions — from any supported format into a typed intermediate representation (IR), applies an ordered transformation pipeline, and emits output in any supported target format.

It is designed for deterministic, reproducible builds of AI configuration.
It never touches the network unless explicitly asked.
It has no configuration files, no local state, and no daemon.

All commands are flat top-level subcommands, like `protoc`, `jq`, and `tar`.

## COMMANDS

### `rulette parse [input...]`

Parse one or more input files (or stdin) into the Rulette IR.
Automatically detects format from file extension and content.
Supports individual files, directories (recursive), and tar archives.

**Options:**

    --from <format>           Force input format detection (auto, skill-md, agent-skills,
                              claude, cursor-mdc, cursor-legacy, codex, windsurf, copilot,
                              gemini, ir-json, ir-toml)
    -o, --out <path>          Write output to file instead of stdout
    --strict                  Fail on parse warnings

**Examples:**

    rulette parse .cursor/rules/typescript.mdc
    rulette parse rules/ --from skill-md
    cat CLAUDE.md | rulette parse --from claude
    rulette parse archive.tar.gz

### `rulette emit [input...]`

Emit IR (from stdin or files) to a target format.

**Options:**

    -t, --to <format>         Target format (required): claude, cursor-mdc, codex, windsurf,
                              copilot, gemini, agent-skills, ir-json, ir-toml
    -o, --out <path>          Output path (file or directory)
    --scope <scope>           Output scope: project (default) or user.
                              When user, resolves --out to user-global config paths
                              (e.g., ~/.claude/skills/ for claude, ~/.cursor/rules/ for cursor-mdc)
    --merge                   Merge multiple rules into a single output file
    --split                   Split into one file per rule (default for directory output)

**Examples:**

    rulette parse rules/ | rulette emit --to claude --out .claude/skills/
    rulette emit --to cursor-mdc --out .cursor/rules/ < rules.ir.json
    rulette parse CLAUDE.md | rulette emit --to codex --merge --out AGENTS.md
    rulette parse ~/dotfiles/ai-rules/ | rulette emit --to claude --scope user

### `rulette convert [input...]`

Parse input and emit to a target format in one step.
Convenience command that combines `parse` and `emit` for the common case.

**Options:**

    --from <format>           Source format (auto-detected if omitted)
    --to <format>             Target format (required)
    -o, --out <path>          Output path (file or directory)
    --scope <scope>           Output scope: project (default) or user
    --merge                   Merge multiple rules into a single output file

**Examples:**

    rulette convert .cursor/rules/typescript.mdc --to claude --out .claude/skills/
    rulette convert rules/ --to codex --merge --out AGENTS.md
    rulette convert ~/dotfiles/ai-rules/ --to claude --scope user

### `rulette inspect [input...]`

Pretty-print the IR for debugging.
Shows parsed structure, metadata, body preview, and detected issues.
Reports which fields will be lost when emitting to each target format.

**Examples:**

    rulette parse .cursor/rules/react.mdc | rulette inspect
    rulette inspect rules.ir.json

### `rulette schema [format]`

Output JSON Schema for the IR or a specific target format.

**Examples:**

    rulette schema ir
    rulette schema claude
    rulette schema cursor-mdc

### `rulette transform [input...]` _(v0.1.1)_

Apply transformations to IR.

**Options:**

    --filter <expr>           Keep only rules matching expression
    --exclude <expr>          Remove rules matching expression
    --rename <from>=<to>      Rename a metadata field value
    --set <field>=<value>     Set a metadata field
    --config <path>           Load transform pipeline from TOML file
    --shell <command>         Pipe each rule body through a shell command

**Examples:**

    rulette parse rules/ | rulette transform --filter 'license == "MIT"'
    rulette parse rules/ | rulette transform --shell 'markdownlint --fix --stdin'
    rulette parse rules/ | rulette transform --config transforms.toml

### `rulette validate [input...]` _(v0.1.1)_

Validate rules against the IR schema and optional policy constraints.

**Options:**

    --policy <path>           Policy file (TOML) defining additional constraints
    --strict                  Treat warnings as errors

**Examples:**

    rulette parse rules/ | rulette validate
    rulette validate --policy org-policy.toml rules/

### `rulette fetch <source>` _(v0.2)_

Fetch rules from a remote source.
Verifies integrity against a lockfile by default.

**Options:**

    --lockfile <path>         Lockfile to verify against (default: rules.lock)
    --allow-mutable           Allow fetching without pinned version (prints warning)
    --no-verify               Skip integrity verification (requires --allow-mutable)
    -o, --out <path>          Output path

**Examples:**

    rulette fetch vercel-labs/agent-skills/react-best-practices --lockfile rules.lock
    rulette fetch https://example.com/rules.tar.gz --out vendor/rules/

### `rulette lock <manifest>` _(v0.2)_

Generate or update a lockfile from a manifest.

**Options:**

    -o, --out <path>          Lockfile output path (default: rules.lock)
    --update <name>           Update only the named package

**Examples:**

    rulette lock rulette.toml
    rulette lock rulette.toml --update react-best-practices

### `rulette verify [lockfile]` _(v0.2)_

Verify that fetched content matches the lockfile.

**Options:**

    --vendor <path>           Vendor directory to verify (default: vendor/rules/)

**Examples:**

    rulette verify rules.lock
    rulette verify rules.lock --vendor .rulette/cache/

### `rulette archive <input...>` _(v0.2)_

Bundle rules into a content-addressed tar archive.

**Options:**

    -o, --out <path>          Output archive path
    --compress <algo>         Compression (none, gzip, zstd; default: gzip)

**Examples:**

    rulette parse rules/ | rulette archive --out rules.tar.gz
    rulette archive rules/ --out dist/rules-v1.0.0.tar.gz

### `rulette unarchive <archive>` _(v0.2)_

Extract and verify a content-addressed archive.

**Options:**

    -o, --out <path>          Extraction directory

**Examples:**

    rulette unarchive rules.tar.gz --out vendor/rules/

## GLOBAL FLAGS

```
--to, -t            Output/target format (json, toml, claude, cursor-mdc, codex, windsurf, copilot, gemini)
--from              Input/source format (auto-detected if omitted)
--out, -o           Output path (stdout if omitted)
--scope             Output scope: project (default) or user
--quiet, -q         Suppress non-error output
--strict            Fail on warnings (including lossy conversion warnings)
--no-color          Disable colored output
--log-level         Log verbosity (error, warn, info, debug, trace)
```

## ENVIRONMENT

    RULETTE_LOG          Log level (error, warn, info, debug, trace)
    RULETTE_COLOR        Force color output (auto, always, never)
    NO_COLOR             Disable color output (standard convention)

## EXIT CODES

    0    Success
    1    General error
    2    Parse error
    3    Validation error
    4    Integrity verification failed
    5    Network error (fetch only)

## FILES

Rulette does not read or write any implicit configuration files.
All paths are explicit CLI arguments.

The following file conventions are recognized by `rulette parse` for format auto-detection:

    SKILL.md                   Agent Skills format (YAML frontmatter + markdown body)
    *.skill.md                 Generic skill (TOML frontmatter + markdown body)
    *.rulette.json             Rulette IR (JSON)
    *.rulette.toml             Rulette IR (TOML)
    CLAUDE.md                  Claude Code rules
    .cursorrules               Cursor legacy rules
    .cursor/rules/*.mdc        Cursor MDC rules
    AGENTS.md                  OpenAI Codex rules
    .windsurfrules             Windsurf rules
    .github/copilot-instructions.md    GitHub Copilot instructions
    GEMINI.md                  Gemini Code Assist rules
    .gemini/settings.json      Gemini Code Assist settings
    rulette.toml               Manifest file (for lock/fetch)
    rules.lock                 Lockfile (for fetch/verify)

The following user-scope paths are resolved by `--scope user`:

    claude          ~/.claude/skills/
    cursor-mdc      ~/.cursor/rules/
    codex           ~/.codex/AGENTS.md
    copilot         ~/.config/github-copilot/instructions.md
    gemini          ~/.gemini/GEMINI.md
    windsurf        ~/.windsurf/windsurfrules
